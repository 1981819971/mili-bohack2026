# 视频搜索等待优化

本次修改集中于主工程源码。按用户要求，未运行测试、未构建或安装 APK，未更新生成的网页和 APK 内嵌副本。以下时序仍需后续真机验证。

## 实现范围

- 抖音相关视频入口复用 `search_in_app`，原生 `DouyinPlayback` 只负责深链搜索、选择结果及全屏。
- 明确点名软件时直接打开软件，不额外搜索视频。
- 搜索框、输入框和搜索结果每 350ms 做一次只读检查，条件满足即继续；不增加全局内容变化事件监听。
- 通用搜索保留原来的各步等待上限，移除提交搜索后再盲目提交并多等 2.5 秒的分支。
- 抖音有可读结果时提前操作；读不到控件时保留原来的 5.2 秒选片、8.2 秒全屏坐标兜底起点。每次只发一个候选手势。
- 最终回执确认后再反馈结果及写入观看记忆。失败后结束本条短流程，不重新打开通用搜索。
- 该轮视频优化未改微信流程。后续按可确认控件提前结束部分等待的范围见《可确认步骤等待优化.md》，读不到控件时保留原时长。

## 时序边界

`DouyinPlayback` 总等待上限为 14 秒；工具回执兜底为 17 秒；外层视频工具预算为 18 秒。它们是不同层的退出上限，不是顺序累加的等待时间。

页面切换至其它软件时停止点击；历史横屏窗口不能作为本次成功证据。这里只确认打开了目标结果的视频页面以及是否全屏，不把手势完成等同于视频已经出画。

## 后续验证重点

页面提前就绪能否减少等待；冷启动及节点不可读时能否走原时长兜底；手动切换页面后是否停止；失败是否仍被错误记录成成功；不同入口是否只打开一次搜索。

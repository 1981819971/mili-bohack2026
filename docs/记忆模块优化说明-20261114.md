# 记忆模块优化说明

本说明对应 `app/` 的记忆实现。本次同步保留公开仓脱敏边界；运行凭据、业务配置与本机产物不随代码上传。

## 现在的调用流程

1. 用户说话后，先检查有效的本地问答缓存与可复用操作经验。
2. 进入智能体时，`MILI_CONTEXT.histMessages(本轮原话, {lite})` 自动汇总当前有效的事实、作息画像，并检索相关历史原文与摘要；普通对话和精简闲聊使用同一入口。
3. 普通模式最多注入 800 字画像、1000 字相关证据及最近 8 条工作消息。精简闲聊分别限制为 260 字、450 字和 2 条，避免长期记忆拖慢首句。
4. 模型可以调用 `remember` 保存事实、偏好和事件，也可以调用 `recall` 查询有效事实与历史。工具回执包含内部事实 id，供后续更正使用；这些 id 不进入给用户的结果话术。
5. 成功完成且适合复用的操作保存为技能，同时提供工具检索正反馈。依赖相对时间、当时屏幕位置的步骤会重新规划，避免把不完整的流程缓存下来。
6. 成功的工具对话也进入原文档案，但不会当成当前闲聊上下文，避免上一件任务影响下一句话。

## 写入、更正与删除

- `MILI_MEMO.add(kind, text, source, {key, replaces, expiresAt})`：`key` 是同一事项的稳定键；`replaces` 指定要更正的旧事实 id；`expiresAt` 可选，使用毫秒时间戳。
- 更正会在一次持久化提交中将旧事实标为失效并追加新事实。旧记录仍可从审计历史查看，当前画像、工作窗口和普通历史召回会排除它。
- 观看平台和最后观看内容分别使用 `video.platform`、`video.last_title`，不会不断累积多个“上次观看”。
- 写盘失败时，事实、技能、路由样本和作息事件回滚内存；保存工具返回失败，不再说已经记住。
- 自动问答缓存有效期为一小时；人工配置不受该缓存时限影响。存在相关有效事实时，优先进入记忆决策，避免旧问答缓存抢答。
- 删除技能时，同时撤销对应的工具检索样本。

## 清空与隔离

`MILI_STORE.clearAll()` 覆盖事实、技能、聊天原文、摘要、画像、作息、路由样本、旧问答缓存、失败经验及智能体内存历史；账号与业务配置保留。

清空会切换记忆代次，模型回复、工具回调和闲时摘要精修的迟到结果不能重新写回已清空的记忆。清空失败会返回失败状态，其他 key 的成功写入也不会掩盖先前的存储错误。

产品与演示空间分别使用 `mili`、`mili_demo` 前缀，聊天、画像、路由样本、事实、技能和作息分开保存。清空演示空间不会物理删除产品空间的记忆。

## 操作经验与作息

- 技能仍然是成功一次即可复用；精确/既有同音匹配范围不扩大。
- 每一步必须完整成功才算重放成功。出现异常、超时、部分完成或后续步骤失败时停止、停用经验并如实反馈，避免从头重复前面已经完成的副作用。
- 工具候选语料增加缓存；学习和撤回后失效，避免每句话重新分词整套工具描述。
- 作息仍需同类事件跨至少三天，取每天代表时刻的中位数；同一天重复操作不能凑够三天。主动提醒继续遵守每日六次预算及事件间隙限制。

## 构建与验证

网页、APK 和离线单文件版都从同一份主入口生成，记忆模块清单取自 `index.html`。离线版本不再读取旧的 `app_boot.js`。修正离线 ESM 加载及页面尾部丢失，并给网页与 APK 的全部页面脚本添加构建版本号。

在 `bohack-elder` 目录运行：

```powershell
npm test
npm run check
npm run eval:memory
```

验证结果：76 项自动测试通过；8 个源文件通过 ESM 语法检查；10 个本地记忆探针全部通过；31 句工具检索回归的注入命中率维持 0.9615。记忆探针是小规模本地回归，不代表真实模型端到端准确率。

离线产物在无头 Chrome 中检查，记忆总线、事实记忆、聊天记忆、智能体和作息模块全部启动，无页面运行错误。测试 APK 通过本地 Android 构建；真实手机的语音、权限及第三方应用操作仍需要装机验收。

本轮没有新增向量数据库、训练模型或云端记忆同步。长期记忆仍保存在本地 `localStorage`；原文归档保留，设备存储满时会报告写入失败。

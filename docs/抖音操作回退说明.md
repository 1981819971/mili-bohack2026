# 抖音操作回退说明

按用户要求，恢复 `mili-bohack-2026-public` 中保留的旧版抖音操作顺序与等待节奏。只回退抖音，不覆盖整份旧文件，以保留其他功能和后续记忆系统改动。

## 恢复的流程

1. 前端调用原有 `playDouyin` 接口，以 `snssdk1128://search` 深链打开搜索页。
2. Java Handler 等待 5200ms 后，在原坐标 `(0.5, 0.43)` 点首条结果。
3. 之后每 1200ms 按旧逻辑判断横屏，尝试文字“全屏观看 / 全屏”。
4. 没有命中文字时，超过 8200ms 后按旧坐标 `0.572 / 0.480` 兜底，同时沿用 `tapAt` 与 `tapAtMetrics` 两套尺寸基准。文字点过但仍未横屏时，超过 11000ms 后沿用原有一次坐标兜底。
5. 判断横屏后停手；超过 16000ms 后在下一次轮询结束。横屏判定仍沿用旧版的旋转、配置方向、窗口及窗口历史规则。

恢复原有关键词清理。新的任务沿用旧版编号机制替换上一轮；Activity 销毁或调用停止接口时，原生编号失效并清除提示。

## 移除与保留

- 删除新增 `DouyinPlayback.java`，不再使用其当前窗口、页面就绪和单次候选点击状态机。
- 移除 `playDouyinTask`、`__onDouyinResult`、JS 请求表及 17 秒回执等待。
- 抖音直达入口恢复直接调用 Java，不再经由新增的视频工具回调链。
- 继续使用“正在查找并打开视频”的进行时回复；派单成功不能当成已播放完成。演示用观看信号仅在原生旧版横屏判断成立时写入。
- 搜索工具沿用旧版派单成功后记录平台和最近片名的行为，同时保留现有记忆系统的结构字段和写入防护；这些记忆不是视频已播放完成的证明。
- 保留现有“正在操作 / 别动屏幕”提醒，由原生单独管理。原有轮询发现最近窗口已是抖音视频详情或横屏播放页时收起，避免视频已打开还等待横屏；没有识别到对应窗口时，提示最多保留 8 秒。提示提前收起不改变原有全屏尝试。
- 不调整语音、微信、其他软件的搜索等待、操作提醒视觉样式或全局工具超时预算。

## 验证状态

仅人工对照旧版源码及当前调用关系，按要求未运行测试、构建或安装，未同步生成的网页和 Android assets。需要重新打包安装后才会影响手机上的版本。本次回退不代表已经验证故障消失，也不额外修改旧流程自身的判断局限。

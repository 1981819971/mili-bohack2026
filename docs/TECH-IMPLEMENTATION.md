## 0. 一句话定位

米粒是**装在老人手机里的一个端侧 Agent**：耳朵和嘴在 Android 原生层，大脑直连大模型做 function calling，
记忆全部落在本机，**后端只做账号、语音与跨设备状态，不参与任何决策**。

它不替老人做决定，只替老人把手机上的动作走完；它的核心主张是「**它记得住**」，
安全求助（头晕、摔倒、打电话给家人）是出厂基础能力，不是进化成果。

## 1. 系统组成与边界

| 层 | 技术 | 负责 | 不负责 |
|---|---|---|---|
| Android 原生壳 | Java（`android/app/src/main/java/com/mili/app/`） | 语音识别、语音合成、无障碍代操作、电话/微信/短信、跌倒检测、桌面宠物、闹钟 | 不参与语义理解与工具选择 |
| WebView 前端 | 原生 JS（`app/`），无框架、无构建 | Agent 决策、记忆、工具路由、界面 | 不直接持有系统权限 |
| Python 后端 | FastAPI / ThreadingHTTPServer，跑在自建 ECS `:9001` | 账号与配对、云端 ASR、TTS 转发、跨设备状态、药箱与体征 | **不参与大模型推理** |
| 大模型 | DeepSeek 官方 `/chat/completions`（SSE + function calling） | 听懂土话、选工具、填参数、组织人话 | 不存任何长期记忆 |

**两套存储，互不同步（已知边界）**：端上 `localStorage` 存记忆与技能；服务端 SQLite `mili.db` 存账号、配对、药箱、体征。
药箱 `S.med` 与体征 `S.vital` 在本机与服务端各存一份，目前**没有同步与冲突解决逻辑**，这是赛前明确接受的取舍。

## 2. 一次交互的全链路

老人按下说话键到听见第一声，实际经过这些步骤：

| # | 环节 | 实现 | 量级 |
|---|---|---|---|
| 1 | 拾音 | `AudioRecord` 16k 单声道，边说边送 | 即时 |
| 2 | 识别 | sherpa-onnx 本地流式中文模型（约 25MB，打进 APK） | 边说边出字 |
| 3 | 端点判定 | 真人声静音满 1.2s 且至少 2 字；引擎还在吐字就一直续命 | 1.2s |
| 4 | 决策 | `app.js` 分层短路 → `agent.js` ReAct | 0ms 或 1.6~3s |
| 5 | 执行 | `agent-tools.js` 67 个工具 → 原生能力 | 视动作而定 |
| 6 | 合成 | 豆包 TTS 2.0，WebSocket 直连，PCM 裸流 | 首音 392ms |
| 7 | 播放 | `AudioTrack` 边收边写；播放中 1.2s 内不判打断 | — |

**为什么 TTS 直连不走后端**：每多一跳多一百多毫秒；直连实测首音 392ms。
要 `pcm` 而不是 `mp3`，省一道解码与解码缓冲。每句一个连接，握手约 110ms，藏在按标点切句的自然停顿里。

## 3. Agent 架构

### 3.1 ReAct 主循环

`app/agent.js` 是一个手写的 ReAct 循环，没有 LangChain 一类框架。核心参数：

| 参数 | 值 | 理由 |
|---|---|---|
| 模型 | `deepseek-flash`（DeepSeek-V4.1-Flash），兜底 `hy3` | 1M 上下文、支持图片；土话理解优于同价位 |
| `maxRounds` | 3 | 闲聊 1~2 轮落地；长链已由专工具（`wechat_message` 等）压成一步 |
| `maxTokens` | 360（工具轮）/ 560（说话轮） | 工具参数只有几十字；老人一句话上限 46 字 |
| `effort` | `low` | 压思维链长度，闲聊不吃推理预算 |
| `temperature` | 0.15（选工具）/ 0.55（说话） | 选工具要确定，说话要自然；0.55 是为修「同一句反复念」的 n-gram 退化 |
| `turnTimeout` | 12s | 真机首字 3.1~7.0s，8s 会站在悬崖边掐断 |
| `totalTimeout` | 30s | 3 轮 + 余量；多步无障碍自动化才用得上 |

> **超时语义（不是「3×12 与 30 打架」）**：每轮实际超时 = `min(12s, 总预算剩余)`，
> 所以第 3 轮只会拿到剩下的时间；总时限是**软上限**，最后一轮保底 4s，
> 极端情况下最多超出 30s 四秒，用于把已经开头的话说完，而不是无声掐断。

每一轮：`turn()` 发请求 → 解析流式 `tool_calls` → `MILI_TOOLS.has()` 白名单校验 → 执行 → 结果回填 `messages` → 下一轮。
最后一轮不带工具，只让它说话。DeepSeek 思考模式下 `assistant(tool_calls)` 必须回传 `reasoning_content`，否则结构化调用会丢，这一点已修。

### 3.2 分层短路链（按实际执行顺序）

前面几层是确定性捷径，只为压延迟；**真正「这句话该干什么」交给模型**。

| 顺序 | 层 | 命中条件 | 耗时 | 说明 |
|---|---|---|---|---|
| 1 | 呼名 | 整句只有「米粒 / 小米粒」 | 0ms | 固定应答 |
| 2 | 寒暄表 | 14 个精确键（你好 / 在吗 / 早上好…） | 0ms | 只读常量，不写记忆、不参与学习 |
| 3 | 问答缓存 | `findRule()` 命中历史答案 | 0ms | 日期类强制跳过，交给第 5 层，避免旧百科抢答 |
| 4 | 技能重放 | `MILI_MEMO.hit(原话)` + 工具序列仍有效 | 0ms | 同一句话办成过，直接重放；演示模式第 1 遍强制挡住 |
| 5 | 日期直答 | 农历 / 星期 / 几号 / 几点 | 0ms | 本地算，绝不联网 |
| 6 | **智能体** | 排除药、身体不适、求救等本地优先类 | 1.6~3s | ReAct 主决策 |
| 7 | 本地硬规则 | 电话 / 微信 / 导航 / 视频 / 电视 / 拍照 / 桌宠 | 0ms | 只在智能体没接住时兜底 |
| 8 | 旧引擎 | `__MILI_LEGACY_EVO` 显式开启 | 0ms | `evolve.js` 已 DEPRECATED，仅断网兜底 |
| 9 | 闹钟 / 药箱 / 快答 | 带钟点的提醒、药名剂量、本地真数据 | 0ms | 必须秒回或必须读本地状态 |
| 10 | 联网兜底 | 以上全不认 | 1~2s | 查必应 + 摘要，原话直出、不加工 |

**一条硬规矩**：智能体已经想过但一个字都没说出来时，**必须停住说「没弄明白」**，不许往下走到「查必应」。
否则「我血压有点高」会被整句丢进搜索引擎，回来的是「我，汉语一级通用规范汉字」——老人以为它在胡说。
「宁可说一句你再说一遍，也不能答非所问」写在代码注释里。

### 3.3 工具层

- **67 个工具、7 个业务域**（通讯、影音、出行、健康、家居、办事、系统等）。
- 全量 schema 18,739 字符，每轮全发既贵又慢，所以**按需注入**（见第 4 节）。
- 执行前过 `MILI_TOOLS.has()` 白名单，模型编造的工具名不会被执行。
- 副作用分级：`call_phone / wechat_message / wechat_redpacket / send_sms / scan_pay / register_hospital / open_map …` 归为 `SIDE_EFFECT`，走确认或只打桩，测试里绝不真发。

### 3.4 系统提示词

| 形态 | 长度 | 用于 |
|---|---|---|
| 完整版 | 约 7.8K 字符 | 带工具的轮次：人格、称呼、日期、硬规矩（微信只走一条路 / 扫一扫直路 / 找不到人就问）、recall 使用边界 |
| `lite` 精简版 | 约 350 字 | 纯闲聊轮：人格 + 今天的日期农历 + 「不超过 28 个字」；不带工具说明、不带失败经验 |

实测完整版每轮重发，光输入编码就几百毫秒；闲聊不需要 67 个工具说明。这是 2026-11-14 的首句提速项。
**工具名与用法只在 `tools` 参数里，不重复写进提示词**（11-11 删掉了 739 字符的重复清单），
所以「schema 从 18,739 降到 3,600」没有被提示词抵消。

### 3.5 诚实性守卫 `guardHonest`

模型最常见的两种「撒谎」都被拦：

1. 工具返回 `ok:false`，它却说「办好了」→ 换成工具原话；
2. 一个工具都没调，它却邀功 → 拦下并说明。

流式播报时，只要本轮已出现过工具失败（`anyFailYet`）或首轮风险高（`riskyFirst`），就**不开流式**，
避免「先念一句办好了，再被改成没办成」。

### 3.6 流式首句起播

11-08 曾因「同一句念两遍」关掉流式。根因不是 TTS，而是**三条出口没有一次性认领**：
`onDelta` 增量、`onStreamEnd` 尾段、`agentSay` 收尾补 `say(r.said)`；而 `streamed` 靠「队列里还有没有东西」猜，猜错就补播一次。

现在的实现（`app/stream-speak.js`，纯逻辑、无 DOM、可跑 Node）：

| 机制 | 做法 |
|---|---|
| 首句门槛 | 中文满 5 字无标点也切；逗号位放宽到 3 字优先；后续句 24 字硬切 |
| 稳定 id | 每段 `turnId-seq`，同时是原生 `miliTtsEnd(id)` 的对账键，跨轮不撞号 |
| turn 归属 | `turnId` 单调递增，上一轮迟到的增量直接丢弃 |
| `claimedEnd` | 尾段只认领一次，重复回调返回空数组 |
| 落盘对账 | 与已念文本一致 → 不补播；是「已念 + 未读尾部」→ 只补尾部；被 `guardHonest` 整体改写 → 不补播 |
| 确定性 `streamed` | `agent.js` 累计 `emitted`，`run()` 回传 `streamed: emitted>0`，前端不再猜 |
| 开启条件 | 只在本轮**不挂工具**时开；挂工具时模型可能说半句转头办事 |
| 现场回退 | `window.__MILI_NO_STREAM = 1` 一行关掉，无需重打包 |

**取舍**：流式已念出的文本是权威，`finalText` 只用于气泡与历史。用「绝不重念」换「极端情况下声音与屏幕可能不一致」。

## 4. 意图识别

### 4.1 为什么不用正则

11-04 之前是正则先跑，凡是沾边的句子全被它抢走，模型根本没上场。两个真机案子：

- 「看看电视」被电视正则接住，用旧包名找悟空失败 → 落到系统浏览器；
- 「我想看红果短剧」被「看视频」正则抢走 → 在浏览器里搜文字，明明手机上装着红果。

这不是模型笨，是它没机会想。现在除了药、身体不适、求救、日期时间这几类**必须本地先办**的，其余一律先让模型想。

### 4.2 检索式工具路由（`app/tool-router.js`）

意图识别＝**中文 BM25 检索 + 模型 function calling**，不是分类器，也不是关键词表。

- 分词：中文 char-bigram（「给我闺女打个电话」→ 给我 / 我闺 / 闺女 / 女打 / 打个 / 个电 / 电话）。
- 排序：BM25，`k1 = 1.5`、`b = 0.75`。
- 三份文档参与打分：工具名、工具描述、域标签（域标签权重 0.25）。
- 每轮注入：**top-8 + 6 个常驻**（`search_web / recall / remember / tell_time / read_screen / go_back`）。
- 分不开时：把整个域的工具带上（域命中加权 0.8）。
- 真没信号：退回全量 67 个，并记 `fallback`。
- **低置信度绝不硬猜**：宁可多给几个工具，也不猜一个错的。

实测（`eval/results.json`，31 条 held-out，赛前冻结）：

> 31 句里有 5 句是「**不该调工具**」（「你是谁呀」「把这个弄一下」「那个东西呢」），
> 它们没有正确答案可排，不能进首个命中的分母。**有效样本 26 句**，
> 另 5 句由「不调工具」的专项行为测试管，不混进工具选择准确率。
> （旧口径把 5 句按必然未命中计入，把真实命中率压低了 14 个百分点。）

| 指标 | 值 |
|---|---|
| 有效样本 | 26 / 31（另 5 句不该调工具，不计入） |
| 检索 Top1 | 0.8846（23/26） |
| 注入集命中率 | 0.9615（25/26，正确工具确实进了注入的 12.87 个里） |
| 注入集 Top1 | 0.8846（23/26） |
| 全量排序 Recall / MRR | 1.0000 / 0.8988 |
| 平均注入工具数 | 12.87 / 67 |
| 注入后 schema 字符 | 约 3,600（全量 18,739） |
| 全量兜底率 | 0 |

**口径必须说清**：这里测的是 `MILI_TOOL_ROUTER.select()` 的 **BM25 检索排序**，
不是 `MILI_AGENT.run()` 的端到端工具选择——模型看到注入集后选哪个，需要真跑模型才能测，本轮没测。
这组数字只作**回归门禁**，不是进化证据，也不能当成「模型选对率」。

### 4.3 改口反馈进入检索

老人追问后换一种说法办成，就把「老人原话 → 第一个成功工具」记成一条检索样本（`corrections`，上限 200 条）。
关键细节：如果这句是上一条追问的回答（120 秒内），**存进样本的键必须是原始请求**，不能是「抖音，对」，
否则老人下回再说原话一个字都命中不了，追问换来的记忆全废。
下次相似说法，这条**真实原话**作为加权文档参与 BM25，排序自然上移——Rocchio 式相关反馈。
权重 `1.2`，满 3 次或跨 3 天升到 `2.2`。

> 2026-11-14 修过一个会破坏阈值的 bug：这段 `learn()` 调用在公开仓被整块复制了两遍，
> 一次改口记两次 `n`，两次改口就凑满 3 次升稳定档。已删重复、加断言锁死。

### 4.4 本地规则的边界

只有四类允许抢在模型前面：**药、身体不适、求救、日期/时间**（外加寒暄与呼名的固定表）。
前两类要读本地真实状态，日期必须 0ms 且不能编。其余一律模型优先。

寒暄表是**出厂固定应答**：只读常量、精确键查表，不写 `S.rules`、不参与学习、不计入演示数字。
这是基础能力，不算进化。

### 4.5 演示模式与「两遍」

演示模式**默认不开**，要从「我的 → 设置 → 比赛演示」手动进入；遍数由演示者点，不自动按记忆跳。

| 遍 | 记忆状态 | 行为 |
|---|---|---|
| 1 | 平台或片名缺一条 | 一句问清平台 + 片名，`blockSkill` 挡住 skill 重放 |
| 2 | 两条都有 | 放行 skill，直达 |

`blockSkill = stepNow() < 2`。按钮用 `data-demostep` 专用属性，避开引导页 9 个同名 `data-step`——混用会把九步向导绑成切遍。
这套设计是为了现场能证明「第一遍不会、第二遍会」，而不是演两遍同一个结果。

## 5. 记忆机制

### 5.1 四层结构

| 层 | 术语 | 实现 | 参数 |
|---|---|---|---|
| 画像 | semantic / core | `compileCore()` 从事实表与作息画像编译，作为 `messages` 首条注入 | ≤ 800 字 |
| 情节 | episodic | append-only 原文日志 + 增量摘要段，BM25 召回 | 摘要 ≤ 620 字/段，最多 6 段 |
| 工作 | working | 最近 8 轮原文；20 分钟 `SESSION_GAP` 隔开跨会话串台 | 8 轮 |
| 程序 | procedural | `MILI_MEMO.skills`：原话 → 工具序列，精确/同音命中即 0ms 重放 | 40 条 |

### 5.2 写入：只追加 + 失效窗口

借鉴 mem0 的 single-pass ADD-only 与 Graphiti 的 validity window：

- 内容没变 → 只累加 `n` 与时间，不覆盖正文；
- 内容变了或用户删了 → 给旧记录打 `validTo` / `supersededBy`，**不物理删除**，再追加新记录；
- 事实上限 60 条、技能 40 条，溢出时同样打失效戳，不静默丢弃。

**事实质量门**：拒收系统说明、元叙述、提示词片段、代码片段。
真机曾把「聊天的记忆分四类：第一类是聊天历史」当老人事实写进画像，之后每轮注入把模型带偏——宁可少记，不许记错。

### 5.3 召回：hybrid + 弃答判定

- 打分 = BM25 × 文档权重 + recency × 0.15；摘要段权重 1.15，原文 1.0；recency 按 30 天线性衰减。
- `query()` 是结构化查询（`contains` / 时间范围），业务代码不再拿正则去 grep 自然语言记忆。
- `hasEvidence()` 用 **query-term coverage** 做弃答判定：纯 BM25 会被「我 / 叫 / 什么」骗过，把「我孙子叫什么」匹配到「我女儿叫小芳」然后编个名字。覆盖不足就明说没记着。

### 5.4 自动上下文压缩

超窗不靠无限扩上下文，靠压缩：

- `WORK_MAX = 8`（压缩后保留原文轮数）、`TRIGGER = 8`（超出多少条触发一次，约 4 轮）、`MAX_SUMMARIES = 6`（超过就链式再压）。
- 锚点 `cutoff` / `cutoffId`，原始日志**只追加不删**，压缩只移动读指针。
- **抽取式**压缩：只留带实体、时间、量词、动作的句子，零额外 LLM 调用、零现场延迟。
- LLM 精修放在 `refine()`，只在闲时显式调用。

借鉴 deepagents 的 `SummarizationMiddleware` 与 Letta 的 `compact.py` / `sleeptime_*`。

### 5.5 统一记忆总线

一键清空曾经只清其中一套，另外几套原封不动。现在 `app/memory.js` 做总线，登记 **5 套**：

| 模块 | 文件 | 内容 |
|---|---|---|
| `memo` | `agent-memo.js` | 事实 + 技能序列 |
| `rhythm` | `app.js` | 作息画像与主动预算 |
| `evo` | `evolve.js` | 旧引擎规则与考卷 |
| `context` | `context.js` | 原文日志 / 摘要 / 画像 |
| `tool-router` | `tool-router.js` | 改口样本 |

`MILI_STORE.clearAll()` 是唯一清空入口，清完写 `clearedAt` 墓碑，模块据此拒绝复活内置项。

## 6. 进化机制

### 6.1 口径（唯一真源）

以 `BOHACK.md §十三` 与 `参赛手册-日新.md §0.5` 为准：

- 核心主张是「**它记得住**」；
- 安全求助、寒暄、日期直答是**出厂基础能力**，不是进化成果；
- **老人没有义务教 AI 做事**，所以不存在「老人教它一句什么」这种叙事。

**驱动源只有两条：老人改口、老人作息。**
两条阈值要分开讲：**作息画像**至少跨 3 天才写进画像；
**技能重放**是另一条闸门——`SKILL_MIN_HIT = 1`，成功一次即可重放，
满 3 次只把检索权重从 1.2 提到 2.2。对外不要把两者合并成「满 3 次才学会」。

### 6.2 A · 老人改口

链路：第一遍它问了平台和片名 → 老人答「抖音，对」→ 办成时用**原始请求**做钥匙，同时写 skill 与检索样本
→ 第二遍同一句原话 0ms 重放，一个字不问。

- 判定：`stable(c) = n ≥ 3 || days.length ≥ 3`。
- 权重：稳定前 1.2，稳定后 2.2。
- 失败也记：`noteFail(工具, 参数, 原因)` 记下「撞过哪面墙」，下次同类事先绕开；只记成功等于每次都从同一面墙开始撞。
- 落点是**检索正反馈**，不是往 `evolve.js` 加正则别名——这是「禁新增意图正则」铁律的具体实现。

### 6.3 B · 老人作息

采集 **7 类事件**：`wake / meal / med / tv / sleep / call / talk`，只记录产品本来就会产生的事件，老人不做任何额外动作。

| 规则 | 值 |
|---|---|
| 样本门槛 | 至少跨 3 个不同日期，同日重复不抵跨天样本 |
| 统计方式 | 30 天滚动窗口，逐类取中位数（不是平均，避免一次熬夜带偏） |
| 主动预算 | 每天最多 6 句 |
| 开口间隔 | 两次至少 5 分钟 |
| 时刻窗口 | 画像时刻前后 12 分钟都算「到点」 |
| 夜间 | 22:00–06:00 只允许「该睡了」 |
| 静音条件 | 在看电视、通话中、录音中、思考中、家人端，一律闭嘴 |
| 每条时间窗 | 每类事件有自己的允许时段，晚上九点不会冒出一句「早」 |

设计依据不是拍脑袋：HALO 2026 对 8000 条人工评分的结论是「太早/太多」占主动式 AI 失败原因的 61.2%，
所以**克制比勤奋值钱**；WSU/CASAS 的结论是最佳时机在「两件事之间」。

当前真机源码采用 `MIN_DAYS = 3`：作息画像需要跨 3 个不同日期；检索样本的次数升权与技能重放是另外两条规则。

### 6.4 回退

设置页「一键清空」→ 五套同退；清空后不再主动开口，技能不再重放。
回退必须连 agent 记忆一起退，否则第二次照样直达，回退就是假的。

### 6.5 明确不算进化的

| 项 | 为什么不算 |
|---|---|
| 头晕摔倒通知家人 | 出厂安全能力，写死在原生层 |
| 寒暄 / 农历日期 0ms 直答 | 性能捷径，只读表 |
| `evolve.js` 的 27 句考卷与正则别名 | 已 DEPRECATED，仅断网兜底 |
| 评测分数涨幅 | 回归门禁，不是学习证据 |

### 6.6 现场怎么证明

「日新 · 两次运行」页把两遍的**提问次数、往返轮数、token、耗时**并排放在一张表里。
第二遍如果是 0 轮 0 token，就是真的从记忆里重放，而不是又跑了一遍模型。这比任何口头解释都硬。

## 7. 端侧能力与后端

### 7.1 原生层的关键取舍

| 能力 | 做法 | 原因 |
|---|---|---|
| ASR | sherpa-onnx 本地流式，模型打进 APK | 小米系统 `SpeechRecognizer` 一直回「caller without permission RECORD_AUDIO」，权限全开也不放行；不如不联网、不看权限脸色 |
| TTS | 豆包 2.0 WebSocket 直连，要 PCM | 少一跳、少一道解码，首音 392ms |
| 代操作 | 无障碍服务读屏 + 点击，配合 `ui_map` 一屏一屏走 | 老人手机上装着什么就用什么，不要求 App 适配 |
| 微信 | `WxFlow` 专路径：搜人、点进去、发出去；扫码/付款码各有直路 | 通用点屏在微信里最容易发错人 |
| 安全 | 跌倒检测、连续未接、反诈提醒、家人通知 | 出厂基础能力 |
| 打断 | 播放开始 1.2s 内不判打断 | 豆包首包抖动 + 回声收敛 |

### 已知边界（如实列出）

1. **流式首句的听感未人耳验收**：CDP 只证明不丢字、尾段不重发，音色与段间衔接要现场听。
2. **TTFA 未在真机量**：目前只有 Node 契约与主观时延，没有正式的分位数。
3. **微信搜索词 `jj` 未定位**：说具体人名时，`WxFlow` 曾把 `Name.searchTerm` 的结果塞进搜索框，仍欠一次现场 logcat。
4. **端上与服务端两套存储不同步**：药箱、体征各存一份，无冲突解决。
5. **作息门槛**：本次同步与真机源码对齐为至少跨 3 天；不要将检索升权的次数门槛套到作息画像。
6. **意图识别的 0.8846 不能外推**：有效样本只有 26 句、赛道特定；它是「这 26 句里工具排第一」的比例，不是通用能力分数。
7. **技能没有独立验证，一次成功就重放**：`SKILL_MIN_HIT = 1`。高风险工具（电话/消息/支付）靠 `SIDE_EFFECT` 与确认卡兜底，但没有「候选→影子→上线」的晋级流程；这是已知设计缺口，不是笔误。
8. **评测只测检索，不测模型**：`run-eval.mjs` 直接调 `select()`，没有跑 `MILI_AGENT.run()`；「注入集 Top1」也不等于模型最终选了它。

## 9. 一分钟讲法

> 一句话进来，先在本地做短路和 BM25 工具检索，只把约 12 个相关工具交给模型；
> 模型用 function calling 选工具、填参数，办完再说话。
> 记忆分四层，超出窗口自动压成摘要，一键能全清。
> 它从老人改口和作息里学；作息至少跨 3 天才写进画像，改口样本另按次数或跨天升权。
> 安全求助是出厂就有的，不算它学会的。
> 它的核心不是「什么都能干」，是「**它记得住**」。

### 评委可能追问

**Q：这不就是调了个 API？**
A：API 只负责「听懂这一句」。真正的工程在三处：67 个工具怎么按需注入（18,739 → 3,600 字符）、
四层记忆怎么压缩与失效、以及现场断网/超时/工具失败时怎么不说假话。`guardHonest` 和分层兜底都是为最后一条。

**Q：为什么不用 RAG 向量库？**
A：端侧、离线、老人手机。BM25 + char-bigram 零依赖、零模型、可解释，改口样本能直接加权；
向量库要 embedding 调用与索引文件，收益在这个规模（几十条事实、几十轮对话）不明显。

**Q：记忆会不会记错？**
A：会，所以有三道闸：写入有质量门（拒收元叙述与代码片段）、更新只追加并打失效戳（可追溯）、
一键清空五套同退。宁可少记，不许记错。

**Q：进化是真的吗？**
A：两条驱动源都能现场演示：改口后同一句话从 2 秒变 0ms 重放；作息至少跨 3 天后，它可以在平时吃药的时刻开口。
「日新」页把两遍的轮数、token、耗时并排放，第二遍 0 轮 0 token 就是证据。

**Q：老人不会用怎么办？**
A：不需要会用。开机自启、桌面一个大按钮、说错也能办、办不成会说人话。
产品假设是「老人不学习」，不是「老人学会用 AI」。

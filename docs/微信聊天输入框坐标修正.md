# 微信聊天输入框坐标修正

现象：已进入聊天页，输入框未打开，后续正文粘贴和发送未生效。

## 核对结果

- 协作者前端适配没有修改微信原生操作流程。
- 此前的等待优化改过 `WxFlow.waitAfterStep`，允许部分步骤在读到控件就绪信号后提前继续；操作提醒也接入了该流程。输入框坐标一直保留旧默认值 `(500, 2265)`，没有随前端合并修改。
- 本次读取手机日志，最近几次点击搜索结果到流程结束约 6.6 秒，与原等待流程一致。日志中的 `ok=true` 仅表示步骤执行完，不能证明消息已经发出。
- 当前真机逻辑分辨率为 1080×2400。人工查看截图，旧输入框点击点位于输入框下方。
- 在同一聊天页验证：点击 `(500, 2265)` 后 `mInputShown=false`；点击 `(500, 2190)` 后 `mInputShown=true`。未填写消息、未点击发送，验证结束后收起键盘。

## 修正范围

- 默认 `inputbox` 改为 `(500, 2190)`。
- 初始化时，仅当已保存的 `inputbox` 完全等于旧默认值 `{x:500,y:2265,w:1080,h:2400}`，才迁移为新默认值。其他标定不覆盖。
- 在已有微信日志中增加输入框、正文粘贴条、发送按钮的实际点击坐标，便于后续定位；不新增正文内容日志。
- 搜索联系人、结果选择、正文粘贴、发送坐标、等待优化及提醒样式保持原样。

此次验证覆盖输入框能否打开，没有执行完整的真实消息发送。该修正基于当前设备的实测位置，其他布局仍以各设备标定为准。

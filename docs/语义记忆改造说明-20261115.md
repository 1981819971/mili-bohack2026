# 语义记忆：显式交代和自动学习

本次将产品的语言记忆入口统一到 `app/semantic-memory.js`。不再只修「帮我记住」，普通聊天和成功操作的学习也经过语义整理。

## 写入流程

1. 显式交代调用 `MILI_AGENT.rememberSemantic`，等待整理、证据校验、持久化后再确认结果。
2. 日常对话在后台调用 `MILI_SEMANTIC.observe`；即使本轮不挂工具，也能提取稳定事实与偏好。本地主入口也接入，因此不限于智能体工具对话。
3. 整理器使用 App 当前配置的模型接口，输入本次原话、最近少量对话和现存事实。输出规范事实、事项 key、原文证据、专名实体、置信度、当前事件和操作意图，不执行工具。
4. 代码检查输出结构、当前原文证据、实体来源、置信度和歧义标志后，才写入事实库。相同事项沿用 key，明确更正使旧事实失效。有确定日期的安排以 event 保存，并要求有效到期时间。
5. 一次分析在当前 UI、内核和 remember 工具之间复用；任务成功后复用语义结果保存操作意图。需要单独整理旧操作时只提取意图，不能再次提取旧事实覆盖新更正。

## 自动记忆的范围

- **事实与偏好**：去口头语、保留否定和条件，整理有证据的普通识别错误。自动整理出的有效事实与显式交代使用同一个存储和页面。
- **习惯**：取消「吃饭、饿、做饭」关键词即记 meal。只接受本人当前明确发生的吃饭、服药、起床、入睡事件；记录使用说话当时的时间，并保留证据。真实点击「吃过了」、内置电视等设备事件直接保留。近两分钟同类事件合并，跨至少三天生成画像的规则不变。
- **工具经验**：成功操作保存规范 intent，保留原始命令作为匹配入口；原命令和规范意图都可精确/既有同音匹配。实际执行过的工具名、参数不被语言整理器改写。路由样本使用规范意图，删除技能同时撤销关联样本。
- **未完成任务**：派单/pending 不等于实际完成，不能写成「已经观看」或学习为成功经验。

这不是向量检索改造，也没有训练模型参数。工具重放没有扩展成任意语义模糊匹配。

## 原文、歧义和失败

规范事实保存在原有 `mili_memory_v2.facts` 中；每条包含 `semantic` 来源信息，区分语言整理和有工具证据的记录。原始转写仍在对话档案中保留，历史检索标明它可能有识别错误，不能与有效事实混为一谈。删除规范事实时，对应的来源片段也会从历史召回中排除。

人名、药名、地址、号码等不按同音自动猜写；专名实体必须有原文或已确认事实的证据。低信心、有歧义、解析失败、模型不可用或写盘失败时，不降级为直接保存原句。显式交代可返回确认问题；自动整理中的不确定内容不进入确定事实库。

清空记忆和切换产品/演示空间使在途分析失效。分析期间被删除或更正的事实不能被迟到结果覆盖。旧的存量事实保留，未进行全量自动改写，以免用猜测覆盖旧数据。

## 成本和验证

日常语义整理独立于回复流，在后台完成，但会增加模型请求和 token 消耗；显式保存需要等待整理。自动记忆可能在回复后才出现在列表中。当前不新增云端数据库，仍使用本机存储和原有模型接口。

自动测试 94 项通过，9 个源文件通过语法检查。新增回归覆盖真实 agent 请求、显式/自动共用入口、事实归并与更正、专名歧义、空结果、事件筛选、异步不阻塞回答、删除/清空/隔离、操作意图及派单未完成等行为。这些测试使用受控模型回执验证代码契约。

另外使用实际模型 API 对合成语句完成 9 组验收：显式错字、自动偏好、未吃饭、问句、假设、名字歧义、当前吃饭、别人吃饭、连续同义归并及更正，全部通过。这是小规模样例验收，不代表对所有语音识别错误都能正确判断。没有使用真实用户历史做模型测试；语音输入与设备操作仍需真机验收。
